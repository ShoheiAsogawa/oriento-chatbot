# コストガード

## 現在の保護

| 層 | 設定 | 効果 |
|---|---|---|
| Cloudflare Budget Alert | アカウント全体 $10（既存・有効） | 使用量ベース料金が閾値へ達した場合にメール通知 |
| セッション日次上限 | 1,000件/日（日本時間） | Turnstile通過後に作成できる会話数を制限 |
| AI回答日次上限 | 1,000件/日（日本時間） | 対象分野かつ回答可能な質問に対するAI Search・推論回数を制限 |
| 会話単位Rate Limit | 12回/60秒 | 短時間の連続送信を抑止 |
| セッションRate Limit | 同一訪問者12回/60秒 | 会話IDの大量作成を抑止 |
| Turnstile | action・hostname・single-use token検証 | 自動化された大量アクセスを抑止 |
| ナレッジファイル | 1ファイル4MB | 大容量アップロードと索引コストを抑止 |
| 保持期間 | 会話365日、顧客1,095日 | D1の無制限増加を防止 |

日次上限は `wrangler.jsonc` の `DAILY_SESSION_LIMIT` と `DAILY_AI_REQUEST_LIMIT` で変更できる。現在の上限は日本時間で会話1,000件/日、AI回答1,000回/日。管理画面の概要に当日の使用数と上限を表示する。Cloudflare AI Gateway側では月15米ドルの支出上限も設定し、月額のハードストップとして併用する。

## R2の保護

監査イベントはQueueで最大50件をまとめ、1つのJSONLオブジェクトとして保存する。1イベントごとにR2へ書き込まないため、Class A操作数を抑える。

本番バケット作成後にLifecycle Rulesを設定する。

- `audit/` prefix: 400日後に削除
- `reports/` prefix: 1,095日後に削除
- バケットの公開アクセス: 無効
- Public Development URL: 無効

## Cloudflareアラートの注意

Budget Alertは情報通知であり、利用を停止するハード上限ではない。集計はリアルタイムではなく日次処理のため、アプリ側の日次上限を費用停止の主な防御として使う。

現在確認できた既存アラートは、`uken.shohei@gmail.com` 宛てのアカウント全体 $10 である。必要なら $5 の早期通知と $25 の緊急通知を追加する。ただし同じCloudflareアカウント上の他プロジェクトの使用料も合算される。

## AIモデル決定後

外部モデルを採用する場合はAI GatewayのSpend Limitsを追加し、金額ベースのハード上限を日次・月次で設定する。Workers AIを継続する場合も、日次AI回答上限とモデル単価を基に上限値を再計算する。
